# PillNote 💊

약을 등록하고, 정해진 시간에 복용 여부를 기록하며, 미복용 시 보호자에게 알려주는 Flutter 기반 복약 관리 앱입니다.

PillNote는 **로컬 우선(local-first)** 으로 동작합니다. 로그인하지 않아도 내 약, 복용 일정, 복용 기록을 기기에 저장해 사용할 수 있습니다. 이메일로 로그인하면 여러 기기에서 데이터를 동기화하고 보호자 알림 기능을 추가로 사용할 수 있습니다.

## 주요 기능

| 기능 | 설명 | 로그인 필요 |
| --- | --- | :---: |
| 오늘의 복약 | 날짜와 시간대별 복용 목록을 확인하고 복용 완료를 기록합니다. | 아니요 |
| 내 약 관리 | 약의 수량, 복용 기간, 1회 복용량, 복용 시각을 관리합니다. | 아니요 |
| 처방전 묶음 | 함께 먹는 여러 약을 하나의 묶음으로 관리하고 한 번에 기록합니다. | 아니요 |
| 의약품 검색 | 식약처 낱알식별 정보로 약을 찾고 e약은요 상세 정보를 확인합니다. | 아니요 |
| 주변 약국 | 현재 위치 주변의 약국을 지도에서 확인합니다. | 아니요 |
| 데이터 동기화 | 로그인한 계정에서 복약 데이터를 이어서 사용합니다. | 예 |
| 보호자 알림 | 보호자를 초대하고 미복용 시 보호자 기기로 Push 알림을 보냅니다. | 예 |

의약품 검색과 주변 약국 조회에는 인터넷 연결이 필요하며, 현재 위치 기반 검색에는 위치 권한이 필요합니다.

## 화면 구성

### 홈

- 날짜별 복약 일정을 시간순으로 보여줍니다.
- 약 또는 처방전 묶음을 한 번에 복용 완료로 기록할 수 있습니다.
- 복용을 기록하면 설정한 1회 복용량만큼 보유 수량이 자동으로 줄어듭니다.

### 약국

- 현재 위치를 기준으로 주변 약국을 지도에 표시합니다.
- 지도를 축소하면 가까운 약국을 묶어서 보여주고, 확대하면 약국 이름과 상세 정보를 확인할 수 있습니다.
- 위치 권한을 사용할 수 없을 때는 서울시청 주변을 기본 위치로 표시합니다.

### 약 관리

- 약 이름으로 의약품을 검색하고 제품 이미지와 상세 정보를 확인합니다.
- 보유 수량, 복용 기간, 1회 복용량, 하루 복용 시각을 설정합니다.
- 함께 먹는 여러 약을 처방전 묶음으로 구성할 수 있습니다.

### 메뉴

- 이메일 로그인과 로그아웃을 관리합니다.
- 복약 데이터 동기화와 계정 데이터를 관리합니다.
- 미복용 판정 시간, 보호자 초대, Push 알림 기기를 설정합니다.

## 데이터 저장 방식

- 약, 묶음, 복용 기록, 알림 설정은 먼저 현재 기기에 저장됩니다.
- 로그인하지 않아도 기본적인 복약 기록과 재고 관리를 사용할 수 있습니다.
- 로그인하면 다른 기기에서도 복약 데이터를 이어서 사용할 수 있습니다.
- 로그인 정보는 운영체제가 제공하는 보안 저장소에 보관됩니다.
- iOS 로그인 정보는 다른 기기로 이전되지 않는 Keychain 영역에 저장하고, Android 앱 데이터는 OS 백업에서 제외합니다.
- 운영 빌드는 HTTPS API만 허용하며, iOS의 임의 평문 통신과 Android의 평문 통신을 차단합니다.

## 앱 실행하기

### 준비물

- Dart `3.12.1` 이상을 포함한 Flutter SDK
- Android Studio와 Android 에뮬레이터, 또는 Xcode와 iOS 15 이상 시뮬레이터

Flutter 개발 환경을 확인합니다.

```bash
flutter doctor
```

패키지를 설치하고 실행 가능한 기기를 확인합니다.

```bash
flutter pub get
flutter devices
```

원하는 기기에서 앱을 실행합니다.

```bash
flutter run -d <device-id>
```

기기가 하나만 연결되어 있다면 간단히 `flutter run`을 사용해도 됩니다.

## 앱 권한

| 권한 | 사용하는 기능 | 거부했을 때 |
| --- | --- | --- |
| 위치 | 현재 위치 주변 약국 검색 | 서울시청 주변을 기본 위치로 표시합니다. |
| 알림 | 보호자 기기의 미복용 Push 알림 | 알림을 받을 수 없으며 나중에 시스템 설정에서 허용할 수 있습니다. |
| 인터넷 | 의약품 검색, 약국 정보, 로그인과 동기화 | 기기에 저장된 기본 복약 관리는 계속 사용할 수 있습니다. |

## 처음 사용하는 순서

### 기본 복약 관리

1. 하단의 **약 관리** 탭에서 `+` 버튼을 누릅니다.
2. 약 이름으로 검색하고 상세 정보를 확인한 뒤 내 약 상자에 추가합니다.
3. 보유 수량, 복용 기간, 1회 복용량, 복용 시각을 설정합니다.
4. **홈** 탭에서 오늘 먹어야 할 약을 확인하고 복용 완료로 표시합니다.
5. 함께 먹는 약이 여러 개라면 **여러 약 하나로 묶기**를 사용합니다.

복용 완료를 기록하면 설정한 1회 복용량만큼 재고가 차감됩니다.

### 로그인과 보호자 연결

1. **메뉴 → 이메일로 로그인**에서 이메일 주소와 6자리 인증번호를 입력합니다.
2. **메뉴 → 보호자 및 Push 알림**에서 보호자의 이메일을 초대합니다.
3. 보호자는 자신의 PillNote 앱에서 같은 방식으로 로그인하고 받은 초대를 수락합니다.
4. 보호자 기기에서 **이 기기 등록·갱신**을 눌러 Push 토큰을 등록합니다.
5. 환자 앱의 **미복용 판정 시간**에서 대기 시간과 보호자 알림 사용 여부를 설정합니다.

## 미복용 알림의 현재 동작 범위

등록한 복용 시각에 설정한 대기 시간이 지나도 복약 기록이 없으면 연결된 보호자에게 알림을 보냅니다.

- 앱이 실행 중일 때 1분마다 확인합니다.
- 앱이 백그라운드에서 다시 활성화될 때 확인합니다.
- 같은 약·날짜·시간에 대한 알림은 중복으로 보내지 않습니다.
- 앱이 완전히 종료된 상태에서는 정해진 시각에 알림 여부를 검사하지 못합니다.

알림을 사용하려면 환자와 보호자가 모두 로그인해야 하며, 보호자가 초대를 수락하고 자신의 기기에서 알림 권한을 허용해야 합니다.

## 프로젝트 구조

```text
pillnote/
├── lib/
│   ├── config/       # 앱 실행 설정
│   ├── app/          # 모듈 생성과 의존성 연결 (AppServices)
│   ├── data/         # 저장소 인터페이스와 SharedPreferences 구현
│   ├── domain/       # 일정 계산, 미복용 판정, 스냅샷 병합 규칙
│   ├── models/       # 약 정보 공통 함수와 복용 일정 모델
│   ├── repositories/ # 약과 처방전 묶음 관리
│   ├── controller/   # 기존 Controller 호출을 위한 호환 진입점
│   ├── screen/       # 온보딩, 홈, 약국, 약 관리, 계정 화면
│   ├── services/     # 복용 기록, 동기화, 보호자 알림, 세션, Push
│   │   └── api/      # HTTP 요청, 오류 처리, 토큰 갱신
│   ├── widgets/      # 공통 UI 컴포넌트
│   └── main.dart
├── assets/           # 이미지와 하단 메뉴 아이콘
├── test/             # 단위 테스트와 위젯 테스트
├── android/
└── ios/
```

화면은 `AppServices.instance`에서 필요한 모듈을 사용합니다. 약·묶음 수정은 `medications`, 복용 기록과 재고 복구는 `intakes`, 서버 백업은 `sync`, 미복용 알림 전송은 `alerts`가 담당합니다. 홈 화면은 `dailyDosePlan()`이 반환하는 예정·완료 목록과 진행률을 표시합니다.

저장소의 JSON 인코딩과 키는 `LocalMedicationStore`에만 있습니다. 다른 모듈은 `MedicationStore` 인터페이스에 의존하므로 저장 방식을 교체할 수 있습니다. 로컬 수정이 저장된 뒤 동기화를 예약하고, 서버 스냅샷을 적용할 때는 다시 동기화를 예약하지 않습니다. 기존 키와 JSON 형식, 삭제·취소 기록은 그대로 유지합니다.

`DoseSchedule`, `MissedDosePolicy`, `SnapshotMerger`는 입력만으로 결과를 계산하며 저장소·네트워크·Flutter UI에 의존하지 않습니다. 서비스의 저장소, API, 세션, 현재 시각은 생성자에서 주입합니다. 테스트는 전역 앱을 초기화하지 않고 독립적인 `AppServices`나 서비스 인스턴스를 만들 수 있습니다. 새로운 로직은 담당 모듈에 추가하고, `Controller`에는 호환을 위한 위임만 유지합니다.

## 운영 릴리스

Android 릴리스는 디버그 키로 대체 서명하지 않습니다. 다음 값을 모두 준비해야 릴리스 빌드가 진행됩니다.

- `android/app/upload-keystore.jks`
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

Git 태그(`v*`)로 실행되는 릴리스 워크플로는 정적 분석과 단위·위젯 테스트를 통과한 뒤 서명된 APK를 만듭니다. 서버의 새 세션 정책을 배포할 때는 동시 토큰 재발급을 막는 이 앱 버전을 먼저 배포한 다음 서버 마이그레이션과 배포를 진행합니다.

## 자주 막히는 부분

### `flutter` 명령을 찾을 수 없습니다

- Flutter SDK가 설치되어 있는지 확인합니다.
- Flutter SDK의 `bin` 디렉터리가 `PATH`에 포함되어 있는지 확인합니다.
- `flutter doctor`를 실행해 Android 또는 iOS 개발 환경의 누락 항목을 확인합니다.

### 약 검색이나 약국 정보가 표시되지 않습니다

- 기기의 인터넷 연결 상태를 확인합니다.
- 약국 화면에서는 위치 서비스와 PillNote의 위치 권한이 켜져 있는지 확인합니다.
- 위치 권한이 없어도 지도를 움직인 뒤 “이 지역 약국 찾기”로 검색할 수 있습니다.

### Push 알림이 오지 않습니다

- 환자와 보호자가 모두 로그인했는지 확인합니다.
- 보호자가 초대를 수락하고 자신의 기기를 등록했는지 확인합니다.
- 보호자 기기의 시스템 설정에서 PillNote 알림이 허용되어 있는지 확인합니다.
- 미복용 알림은 앱이 실행 중이거나 다시 활성화될 때 판정됩니다.

### 위치 권한을 거부했습니다

약국 화면은 서울시청을 초기 지도 중심으로 표시하며 현재 위치가 아님을 안내합니다. 지도를 움직인 뒤 지역 검색을 누르거나, 현재 위치 사용을 선택하고 위치 권한을 허용하세요.

## 복약 화면 흐름

하단 메뉴는 홈 → 내 약 상자 → 약국 → 설정 순서입니다. 흰 배경, 왼쪽 제목, 파란 주요 버튼은 로그인 화면과 공통으로 사용합니다.

스크롤 화면은 공통 `PageScrollView`를 사용합니다. 내용이 화면 안에 들어오면 스크롤과 튕김을 막고 제목을 원래 크기로 유지합니다. 내용이 넘칠 때만 스크롤에 맞춰 제목이 30px에서 20px로 줄어 상단에 고정되고, 부제목은 먼저 서서히 사라집니다. 맨 위로 돌아오면 복원됩니다. 키보드, 창 크기, 큰 글씨 설정으로 표시 공간이 달라지면 스크롤 가능 여부를 다시 판단하며, 지도 등 내부 영역의 스크롤은 헤더에 영향을 주지 않습니다.

- 내 약 상자는 개별 약의 이름·함량, 일정, 선택한 보유 수량을 먼저 보여줍니다. 약 묶음은 별도 관리 화면에서 공통 일정을 설정합니다.
- 약 추가는 검색 또는 직접 입력 → 약 확인 → 복용 시간·기간 → 선택 사항인 수량 관리 → 저장으로 이어집니다. 종료일 없이 계속 복용할 수 있으며 일정은 나중에 정해도 됩니다.
- 홈의 약 이름은 상세 화면을 엽니다. 체크 버튼으로만 복용을 기록하고, 완료 체크 또는 실행 취소로 기록을 취소할 수 있습니다. 수량이 없거나 부족해도 기록을 남길 수 있습니다.
- 같은 약의 같은 시간에 개별 일정과 여러 묶음 일정이 겹치면 하나의 복용 건으로 표시하고 보호자 알림도 같은 기준을 사용합니다.
- 약 보관은 약과 지난 기록을 유지하면서 향후 일정에서 제외합니다. 다시 관리하기로 복원할 수 있습니다. 복용이 종료된 약은 보관·종료 목록에서 기간을 수정할 수 있습니다.
- 수량은 실제 차감된 양만 취소 시 복구합니다. 취소 기록과 삭제된 묶음은 동기화에 남겨 오래된 백업에서 다시 나타나는 것을 방지합니다.
- 보호자 화면에서 알림 상태를 확인하고 사용자가 직접 알림을 켭니다. 놓친 복용 알림은 앱 실행 중 또는 재개 시 확인하며 백그라운드 복용 알람은 제공하지 않습니다.
