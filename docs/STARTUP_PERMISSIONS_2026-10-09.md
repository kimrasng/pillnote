# 첫 실행 권한 요청

2026-10-09 JST. 앱의 첫 화면에서 필요한 권한을 차례로 요청하도록 적용했다.

- iOS: 알림(알림창·소리·배지) → 앱 사용 중 위치.
- Android: 알림 → 위치 → 알람 및 리마인더. 정확한 알람은 해당 앱의 시스템 설정
  화면에서 허용하거나 뒤로 돌아오면 다음 처리를 진행한다.
- 이미 허용된 권한과 영구 거부된 위치 권한은 확인만 한다. 네이티브 요청을 하나씩
  기다리므로 권한 창이 겹치지 않는다. 인터넷·재부팅 수신은 별도 사용자 요청 창이 없는
  manifest 권한이고, 백그라운드 위치·카메라·사진 등의 사용하지 않는 권한은 추가하지 않았다.
- 모든 권한을 허용하면 기존 온보딩이나 홈으로 진입한다. 하나라도 미허용이면 해당
  권한과 기능 제한을 안내하고 **다시 권한 허용하기 / 그냥 이용하기** 선택을 제공한다.
  알림 미허용은 이 기기에서 복약 알림 수신 불가, 위치 미허용은 현재 위치로 주변
  약국 찾기 불가(지도에서 지역 선택은 가능), Android 정확한 알람 미허용은 도착 지연
  가능성을 안내한다. 상태 조회 오류는 거부와 구분해 `확인 필요`로 표시한다.
- 다시 허용하기는 미허용 권한만 요청한다. 요청 후에도 알림·위치 권한이 없으면 앱의
  기기 설정을 한 번 열고, 앱 복귀 시 다시 확인한다. Android 정확한 알람은 전용 설정
  화면으로 연결한다. 그냥 이용하기를 누르면 기본 복약 관리를 계속 이용할 수 있다.
- `startup_permissions_requested`는 설치 단위 로컬 정보다. 복약 데이터 초기화와
  다른 계정 로그인 시에도 유지되며 서버에 동기화하지 않는다. 기존 설치는 새 버전을
  처음 실행할 때 확인한다. 모든 권한을 허용하거나 그냥 이용하기를 선택해야 완료로
  저장하며, 완료 후 재실행에서는 일괄 요청하지 않는다. 선택 전에 앱을 종료한 경우
  다음 실행에서 안내를 계속한다.
- 권한 요청과 복용 시간 알림 사용 스위치는 별개다. 첫 실행 권한 요청은 기존 알림 사용
  선택을 바꾸지 않고, 권한 처리가 끝난 뒤 현재 설정에 맞춰 예약 상태를 갱신한다.
- 로그인 상태에서는 권한 처리 후 보호자 Push 기기 등록 상태도 갱신한다. 알림 권한
  자체는 Firebase 설정·로그인·네트워크 없이 로컬 플러그인으로 요청한다.
- 위치 권한 요청 단계에서는 현재 좌표를 조회하거나 서버로 보내지 않는다.

`StartupPermissionService`가 요청 순서·중복 실행·완료 저장을 담당하고,
`StartupPermissionGate`가 첫 프레임 뒤 자동으로 요청을 시작해 결과를 안내한다.
안내는 사용 가능한 화면의 상하 중앙에 배치하며, 작은 화면과 큰 글씨에서는 스크롤된다.

재요청 분기는 [Apple 알림 권한 문서](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/requestauthorization(options:completionhandler:))와
[Geolocator 권한·설정 안내](https://github.com/Baseflow/flutter-geolocator/blob/main/geolocator/README.md)를 참고했다.

## 검증

- 거부 후 선택 흐름 수정 후 `flutter test`: 로컬 백엔드 연동을 포함한 전체 173개 통과.
- `test/startup_permission_test.dart`: 첫 실행·거부·오류·중복 실행·재실행·데이터
  초기화·네이티브 요청 분기·설정 복귀 시점·중복 재요청·단일/전체 거부·큰 글씨에서의
  두 선택지 접근 등을 27개 테스트로 검증했다.
- `flutter analyze`: 문제 없음.
- 초기 일괄 요청 버전에서 `flutter build apk --debug`와
  `flutter build ios --simulator --debug`가 성공했다.
- 거부 후 선택 흐름 수정 후 일반 앱의 `flutter build ios --simulator --debug`도
  성공했다. 네이티브 검증용 임시 시뮬레이터는 정리했다.

- 거부 후 선택 흐름 수정 후 iOS 26.5 / iPhone 17 Pro 임시 시뮬레이터 네이티브
  테스트 1개 통과. `integration_test/startup_permissions_test.dart`에서 알림·위치
  미허용 항목 표시, 두 선택지, 선택 전 미완료 상태, 그냥 이용하기 선택 후 완료 저장과
  앱 진입, 로컬 데이터 초기화 후에도 다음 실행에서 중복 요청하지 않는 동작을 확인했다.
  기기 설정 복귀와 재허용 성공·실패는 모의 네이티브 API 및 위젯 테스트로 확인했다.

임시 QA 기기의 알림 허용 클릭은 자동 승인 검토에서 거절되어, 네이티브 검증은
권한 거부 흐름으로 수행했다. 허용·기존 권한·Android 정확한 알람 등의 분기는 모의
네이티브 API 테스트로 검증했다. 사용자 기기의 권한 상태는 변경하지 않았다.
