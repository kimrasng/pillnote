# 계정 전환 시 로컬 데이터 분리

2026-10-08 JST. A 로그아웃 후 B 로그인 시 A의 로컬 데이터를 먼저 삭제하고
B의 서버 데이터만 가져오도록 수정했다.

## 적용한 동작

| 흐름 | 결과 |
| --- | --- |
| 비회원 사용 → 최초 A 로그인 | 비회원 데이터를 A 서버 데이터와 병합하고 A에 저장 |
| A 로그아웃 → A 재로그인 | A의 로컬 변경을 유지하고 서버와 동기화 |
| A 로그아웃 → B 로그인 | A의 약·묶음·복용 기록·설정과 알림 예약을 먼저 삭제한 뒤 B 데이터 조회 |
| B의 백업이 없거나 비어 있음 | 약·묶음·복용 기록이 없는 상태 유지 |
| B의 서버 조회 실패 | 빈 상태 유지, A 데이터 표시·업로드 방지 |
| A → B → A | B의 로컬 기록을 삭제한 뒤 A의 서버 데이터를 다시 조회 |

앱 설치 식별자와 온보딩 완료 상태는 유지한다. 복용 시간 알림 사용 설정은 계정
전환 시 초기화하므로 새 계정에서 다시 켜야 한다. 서버 백업은 계정 전환으로 삭제하지
않는다. 이전 계정의 동기화하지 않은 로컬 변경은 요청한 삭제 정책에 따라 제거된다.

## 수정 내용

- `local_data_owner_id`를 기록하고 로그아웃·세션 만료 뒤에도 유지한다. 이전 계정
  기록을 비회원 데이터로 판단해 새 계정에 이전하지 않는다.
- 세션 저장 전에 로컬 데이터 준비를 기다린다. 다른 계정이면 기록, 이전·새 계정의
  동기화 기준, 복용 시간 알림을 정리한 뒤 로그인 상태를 공개한다. 로컬 삭제나 소유
  계정 저장이 실패하면 새 계정 로그인 완료를 공개하지 않는다.
- 앱 시작 시 복원된 세션과 로컬 소유 계정을 확인한다. 기존 버전에서 로그인된
  세션이 있으면 해당 계정에 기록을 귀속하고, 로그아웃 상태이면 기존 동기화 메타데이터로
  소유 계정을 추정한다. 소유 계정이 모호한 기존 캐시는 새 비회원 기록으로 취급하지 않는다.
- 이전 계정의 HTTP 응답을 기다리지 않고 계정 전환을 진행한다. 동기화의 로컬 쓰기는
  직렬화하고 세션·데이터 세대를 확인해 늦은 응답이 삭제한 기록이나 동기화 기준을
  복구하지 못하도록 한다. 복용 기록 작업의 후속 재고·묶음 쓰기도 계정 전환 뒤 중단한다.

## 검증

`test/account_data_isolation_test.dart`는 최초 비회원 이전, 다른 계정의 기존·빈·없는
백업, 서버 조회 실패, 동일 계정 재로그인, 재시작·세션 만료, 기존 버전 데이터,
지연된 조회·업로드·토큰 갱신·복용 기록 쓰기, 로컬 삭제 실패를 모의 API로 확인한다.

- `flutter test`: 로컬 백엔드 연동을 포함한 전체 139개 테스트 통과.
- `flutter analyze`: 오류·경고·정보 없음.
- `flutter build apk --debug`: Android debug APK 빌드 성공.
- `flutter build ios --simulator --debug`: iOS 시뮬레이터 앱 빌드 성공.

실제 사용자 계정이나 운영 데이터를 조회·변경하지 않았다. 기존 버전이 이미 다른
계정의 서버에 병합한 기록은 이번 변경으로 자동 제거하지 않는다.
