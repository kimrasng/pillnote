# 앱 종료 중 복용 기록 확인 수정

작성: 2026-10-07 (JST).

이 문서는 미복용 검사 기능을 처음 추가한 0.1.2 기준 기록이다. 이후 모니터링 집계를
추가한 최신 백엔드는 0.1.3이며 배포 시 0006까지 마이그레이션한다.
최신 배포 순서는 [관리 웹 안내](../../pillnoteadmin/README.md)를 참고한다.

## 변경한 동작

백엔드 0.1.2는 Cloudflare Cron으로 1분마다 동기화된 복약 일정과 복용 기록을 검사한다.
환자 앱이 종료되어도 설정한 대기시간이 지나고 복용 기록이 없으면, 연결을 수락하고
푸시 기기를 등록한 보호자에게 기존 FCM 알림을 발송한다.

- 기존 암호화 백업에 시간대를 포함한다. 약 이름·복약 이력은 별도 평문 테이블로 옮기지 않는다.
- D1에는 검사 시작 시각·다음 검사 시각과 인덱스만 추가한다.
- 개인·묶음 일정 중복, 시작·종료일, 보관·삭제, 복용 취소를 앱과 동일한 규칙으로 판단한다.
- 전날 늦은 복약과 자정 이후 대기시간도 확인한다. 예정 건의 확인 시한은 최근 24시간이다.
- 앱 전경 검사와 서버는 같은 event key로 중복 전송을 방지한다. 기존 실패 재시도는 최대 3회다.
- 검사를 마친 사용자는 다음 복약 시각까지 대기하고, 남은 건과 전송 실패는 다음 분에 재시도한다.
- 검사 lease와 revision 검증으로 Cron 동시 실행과 복용 기록 동기화 충돌을 방어한다.
- 알림 해제, 보호자 연결 해제, 백업 삭제, 계정 삭제가 검사에 반영된다.
- 구버전 백업에는 시간대가 없으므로 새 앱으로 한 번 동기화한 뒤 서버 검사가 시작된다.
- 앱은 백그라운드 전환 시 남은 편집을 동기화하고 실패한 편집은 재개/다음 검사 때 재시도한다.

운영 모니터링 기획은 [MONITORING_PLAN_2026-10-07.md](MONITORING_PLAN_2026-10-07.md)에 있다.
외부 감시·관리 화면·Crashlytics는 이 변경에서 구현하지 않았다.

## 반영 절차

기존 0.1.1 배포에 대한 확인 결과와 이번 0.1.2의 로컬 검증은 다르다.
아래 신규 마이그레이션·Worker·앱을 실제로 반영해야 종료 중 검사 기능이 활성화된다.

백엔드 디렉터리에서:

```sh
cd /Users/kimrasng/dev/pillnotebackend
npm run d1:migrate:remote
npm run deploy:worker
npm run verify:production
```

첫 명령은 `0005_server_missed_dose.sql`을 기존 운영 D1에 추가하며, 새 DB나 secret은 필요하지 않다.
Worker 설정에 이미 1분 Cron을 넣었으므로 재배포하면 함께 적용된다.
Cloudflare Workers → pillnote-backend → Settings → Triggers에서 확인한다.
Cron 변경 전파에는 최대 15분이 걸릴 수 있으며, 과거 실행 목록 표시에는 추가 지연이 있을 수 있다.

Android/iOS는 현재 수정된 앱을 기존 서명 설정으로 빌드·배포한다. 스토어에 이미 배포한
build number보다 높은 번호를 사용한다. 사용자는 업데이트 후 로그인하여 한 번 온라인
동기화하고 보호자 연결·알림 사용 여부를 확인한다. 시간대가 없는 기존 앱은 계속 전경
검사만 수행한다.

## 실제 기기 확인

1. 환자·보호자 테스트 계정으로 초대·수락과 보호자 푸시 권한·기기 등록을 확인한다.
2. 미래의 복약 시각을 저장하고 환자 앱에서 동기화 완료를 확인한다.
3. 환자 앱을 완전히 종료한다. 보호자 기기도 배경 상태에 둔다.
4. 설정 대기시간과 다음 Cron 검사 이후 보호자 푸시 수신을 확인한다.
5. 별도 일정에서 복용을 완료해 동기화하고 동일 조건에서 알림이 오지 않는지 확인한다.
6. 보호자 알림 해제·연결 해제·백업 삭제 후 새 알림이 발생하지 않는지 확인한다.

FCM 수락은 실제 기기 수신·사용자 열람과 다르다. 오프라인에서 복용했어도 서버에 아직
기록이 없다면 확인 요청을 받을 수 있다. OS가 동기화 전에 앱을 강제 종료하면 마지막
기록 전송도 완료되지 않을 수 있다. 안내 문구는 실제 미복용 확정 대신 복용 기록 확인으로 유지한다.

## 로컬 검증 결과

이번 수정의 로컬 검증 결과다. 운영 배포·실기기 푸시 수신은 별도다.

- Flutter 정적 분석: 오류 없음.
- Flutter 단위·위젯·로컬 백엔드 연동: 91개 통과.
- 백엔드 회귀 테스트: 75개 통과.
- Cloudflare 로컬 Worker/D1: 기존 기능 14개, 보안 8개, 앱 요청 없는 Cron 3개 통과.
- Android 네이티브 복약 흐름·저장소·Firebase·시간대 조회 통과. 공개 API 연결은 시뮬레이터 메모리 압박 이후 단독 재실행에서 통과.
- iOS 시뮬레이터 복약 흐름·공개 API·저장소·Firebase·시간대 조회: 3개 통과.
- Android APK·iOS 시뮬레이터 앱 정상 진입점 빌드와 테스트 기기의 정상 앱 복원 완료.
- 이메일·FCM 발송 응답은 테스트용 대체/모의 제공자로 검증했으며 실제 기기 푸시 수신은 배포 후 별도 확인.
- Worker dry-run 패키징 통과. 운영 DB/Worker는 이번 작업에서 변경하지 않음.
