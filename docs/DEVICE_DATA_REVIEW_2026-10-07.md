# 로그인 기기 정보와 개인정보 검토

2026-10-07, 한국 이용자에게 서비스를 제공하는 경우를 기준으로 정리했습니다. 구현 범위와 배포 준비 기록이며, 전체 서비스의 적법성을 확정한 의견은 아닙니다.

## 이번 구현

기존 관리자의 Android/iOS 값은 푸시 등록 수였습니다. 알림 거부·APNs/FCM 실패 기기가 빠지는 문제를 피하기 위해 `/v1/app-devices/:id`에서 로그인 기기를 별도로 보고합니다. 앱 설치별 기존 임의 ID와 유효한 갱신 세션을 연결하며 재접속·토큰 회전은 같은 기기를 중복 집계하지 않습니다. 서버 로그아웃·전체 로그아웃·만료가 집계에 반영됩니다. 오프라인 로그아웃 실패는 서버 만료 전까지 반영이 늦을 수 있습니다.

구버전 세션은 플랫폼 미확인 세션으로 표시합니다. 기존 푸시 수에서 로그인 수를 추정하거나 과거 기종을 만들어 채우지 않습니다. 새 앱 설치 후 로그인·시작·복귀 시 보고해야 분류됩니다. 최근 기기 정보 수신 시각은 앱이 지금 실행 중임을 의미하지 않습니다.

| 구분 | 항목 | 처리 |
| --- | --- | --- |
| 로그인 기기 관리 | 계정, 앱 설치별 임의 ID, Android/iOS, 유효 세션 연결, 등록/최근 정보 수신 시각 | 로그인한 앱이 보고. 계정과 연결된 개인정보로 취급 |
| 선택 기기 정보 | 기종 코드, OS 버전, 앱 버전·빌드 | 기본 꺼짐. 설정 → 기기 정보 제공에서 선택. 미동의 시 로그인·복약·알림 이용 가능 |
| 수집하지 않는 항목 | 사용자 지정 기기 이름, 전화번호, 일련번호, IMEI, 광고 ID, 위치 | 이 기기 정보 기능에서는 읽거나 보내지 않음 |

선택 정보 철회 시 서버의 상세 필드를 NULL로 덮어씁니다. 오프라인이면 로컬 선택을 먼저 저장하고 다음 접속에 서버 반영을 다시 시도합니다. 기기 등록은 계정 삭제 시 cascade 삭제하고, 유효 세션이 없고 마지막 접속 후 30일이 지난 기록은 Cron에서 정리합니다. 관리자에는 토큰·설치 ID·세션 식별자 원문을 반환하지 않습니다. 기존 푸시 등록·위치 약국 검색 기능은 이번 기기 정보 기능과 별도 처리입니다.

## 법적 판단의 기준

기기 정보를 운영자 화면에서 조회하는 행위 자체가 일률적으로 금지되는 것은 아닙니다. 계정과 연결되어 개인을 알아볼 수 있거나 다른 정보와 쉽게 결합되는 정보라면 개인정보 보호법 적용을 전제로 처리해야 합니다. 수집·이용 근거(동의, 계약 이행에 필요한 처리 등)를 실제 목적에 맞게 정하고, 최소한의 항목만 처리해야 합니다. 개인정보 처리방침에 목적·항목·보유 기간·권리 행사 방법 등을 공개해야 합니다. 선택 동의 화면 하나가 서비스 전체의 처리방침·국외 이전 요건을 대신하지는 않습니다.

근거: [개인정보 보호법 제15조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335387), [제16조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335671), [개인정보 보호법](https://www.law.go.kr/법령/개인정보보호법).

복약·건강 정보는 민감정보에 해당할 수 있으므로 서버 백업과 보호자 전달에 대한 근거와 동의를 별도로 검토해야 합니다. 암호화하거나 관리자에서 약 이름을 숨겼다는 이유만으로 해당 의무가 없어지지는 않습니다.

근거: [민감정보 처리 기준 — 생활법령정보](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=3&cnpClsNo=1&csmSeq=1257&menuType=cnpcls&popMenu=ov).

Cloudflare·Firebase·Resend를 통한 처리위탁/보관/제공이 실제 국외 이전에 해당하면 제28조의8의 허용 근거와 고지·보호조치를 충족해야 합니다. 별도 동의가 모든 경우의 유일한 근거는 아니며, 계약 이행에 필요한 위탁·보관의 공개/고지 등 법이 정한 요건에 맞는지 확인해야 합니다. 이번 검토는 각 공급자의 실제 이전 국가·계약·보관 정책까지 확인한 것은 아닙니다.

근거: [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334957).

## 앱 정식 배포 전 운영자가 확정할 내용

1. 공개 개인정보 처리방침 URL과 앱 내 접근 경로. 저장소에서는 서비스 전체의 처리방침·동의 기록 기능을 확인하지 못했습니다. 외부 공개 문서가 있다면 아래 항목을 대조하세요.
2. 계정·로그인 기기 관리의 처리 목적, 수집 근거와 항목/보유기간. 선택 기기 정보 동의와 미동의·철회 방법을 반영하세요.
3. 복약 정보 서버 백업에 대한 민감정보 처리 근거/별도 동의와 보호자 제공 범위·동의. 현재 기기 정보 선택 화면은 복약 정보 동의 화면이 아닙니다.
4. Cloudflare·Google Firebase·Resend의 실제 이전 국가, 이전 시기/방법, 수탁자와 연락처, 목적·보유기간, 거부 절차/효과를 공급자 계약과 설정에 맞게 확정하세요. 한국 도메인이라는 이유로 국내 보관이라고 표시하지 마세요.
5. 운영자 열람·접속기록, 권리 행사/삭제 요청 창구, 앱스토어의 데이터 공개 내용을 실제 구현과 맞추세요. 만 14세 미만 이용자를 받는다면 법정대리인 절차도 검토해야 합니다.

이 사항을 확정하기 전에는 '법적으로 문제없음' 또는 '개인정보를 수집하지 않음'이라고 안내하면 안 됩니다. 정식 출시 전 한국 개인정보 실무 전문가에게 실제 처리방침·동의와 공급자 계약을 검토받는 것을 권합니다.

## 검증과 사용자 적용

백엔드 Node 97개, 모바일 테스트 93개, 관리자 Node 29개, 실제 Worker/D1 25개, 내부 RPC/D1 16개 통과. Flutter analyze 및 Android APK·iOS 시뮬레이터 앱 빌드 통과. 운영 배포 기록은 관리 프로젝트의 DEVICE_OPERATIONS_2026-10-07.md에 기록합니다.

서버/관리 웹만 갱신해서 이미 배포된 앱의 기종을 읽을 수는 없습니다. Android/iOS 앱을 다시 빌드·배포하고 로그인해 접속해야 합니다. 상세 기종을 보려면 앱의 선택 설정을 켜야 합니다. 실제 두 OS 기기에서 알림 권한 거부 상태의 로그인 집계, 설정 제공/철회, 로그아웃 수치 변화를 출시 전에 확인하세요.
